## 1. Key Findings

1. **Controller Symbols & VHCI Exposure (`esp-radio 1.0.0-beta.1` / `esp-wifi-sys` `libbtdm_app.a`)**:
   - `libbtdm_app.a` in `esp-wifi-sys-esp32-0.3.0/libs/` contains the RivieraWaves Bluetooth Classic BR/EDR Link Controller (`lc.o`, `ld_acl.o`, `ld_pscan.o`, `ld_iscan.o`) and Link Manager (`lm.o`), alongside BLE (`llc.o`, `llm.o`, `lld.o`), exposed via `btdm_controller_init`, `btdm_controller_enable`, `API_vhci_host_send_packet`, and `API_vhci_host_register_callback`.
   - However, `esp-radio 1.0.0-beta.1` (`src/ble/btdm.rs:375`, `src/ble/os_adapter_esp32.rs:377-380`) hardcodes `mode: esp_bt_mode_t_ESP_BT_MODE_BLE` (`1`), `bt_max_acl_conn: 0`, and `const MAX_HCI_PACKET_LEN: usize = 259` in `HciOutCollector` (`src/ble/mod.rs:80, 174-177`), which drops Classic A2DP ACL frames (`672..1021` bytes).
   - Furthermore, no `no_std` Bluetooth Classic host stack (`L2CAP`, `SDP`, `AVDTP`, `AVRCP`, `SBC`) exists in the Rust ecosystem.

2. **DRAM (`dram_seg`) & Heap Budget with Wi-Fi + Bluetooth Coexistence**:
   - `louder-esp32-app` currently occupies `100.00%` of internal `dram_seg` (`196,608` bytes = `192 KB`, `0x3FFB0000..0x3FFE0000`):
     - `.data` + `.data.wifi`: `16,168` B
     - `.bss`: `143,912` B (`64 KB` `esp_alloc` Wi-Fi heap + `31.2 KB` `BSS_BUFFERS` + `22.8 KB` `STATIC_MP3_DEC`)
     - `.stack`: `36,528` B (`0x3FFD7150..0x3FFE0000`)
   - Initializing the BTDM Classic controller requires reserving `CONFIG_BT_RESERVE_DRAM = 0xDB5C` (`56,156` bytes = `54.84 KB`) for hardware Exchange Memory (`0x3FFAE6E0..0x3FFBDB5C`), shrinking `dram_seg` from `192 KB` down to `136 KB`.
   - Running Wi-Fi STA and Bluetooth Classic simultaneously on ESP32 in internal DRAM alone is physically impossible without first initializing `4 MB` external PSRAM (`esp_hal::psram`) and moving `ring_storage` (`16 KB`), `nvs_buf` (`16 KB`), and `STATIC_MP3_DEC` (`22.8 KB`) out of `.bss` into PSRAM (`~55 KB` DRAM savings).

3. **C `recovery` Partition (`0x10000`, `I2S-4MFlash-1681`) Capabilities**:
   - Bluetooth Classic A2DP Sink is already compiled into the C `recovery` partition (`0x10000`) (`CONFIG_BT_ENABLED=y`, `CONFIG_BTDM_CTRL_MODE_BR_EDR_ONLY=y`, `CONFIG_BT_SINK=y`, `components/driver_bt/bt_app_sink.c`), reporting `"bt_status": 0` in `status.json`, and activates when NVS key `"enable_bt_sink"` is set to `"1"` in partition `0x9000`.
