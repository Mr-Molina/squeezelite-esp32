- **Root Cause Analysis**:
  - In `rust/crates/louder-esp32-app/src/main.rs:1418`:
    `const SPI0_CACHE_SCTRL_REG: *const u32 = 0x3FF4_303C as *const u32;`
  - Per ESP32 Technical Reference Manual and ESP-IDF `soc/spi_reg.h`:
    Offset `0x3C` is `SPI_SLAVE1_REG(0)`.
    Offset `0x54` (`0x3FF4_3054`) is `SPI_CACHE_SCTRL_REG(0)`.
  - Line 1429 checks: `let ext_sram_mapped = (cache_ctrl1 & (1 << 1)) == 0 && (spi0_sctrl & (1 << 2)) != 0;`.
  - Reading `SPI_SLAVE1_REG` instead of `SPI_CACHE_SCTRL_REG` yielded `bit 2 == 0`, causing `ext_sram_mapped` to evaluate `false` and `psram_avail_bytes` to evaluate `0`.
  - In `main.rs:2442`, when `format == AudioFormat::Flac` arrives, the check `if psram_avail_bytes >= 1_048_576` fails. Execution enters the `else` block (line 2457), which bypasses `FlacDecoder` allocation, leaves `pipeline.decoder` as the default `ActiveDecoder::Pcm`, and calls `pipeline.sink.set_mute(true)`.
  - Under the 1-flash circuit breaker constraint of `WO-196`, no second flash was attempted.

## 3. Known Risks & Remediation Plan

1. **Remediation for Gate 3 MMIO Register Offset**:
   In `rust/crates/louder-esp32-app/src/main.rs:1418`:
   Change:
   ```rust
   const SPI0_CACHE_SCTRL_REG: *const u32 = 0x3FF4_303C as *const u32;
   ```
   To:
   ```rust
   const SPI0_CACHE_SCTRL_REG: *const u32 = 0x3FF4_3054 as *const u32;
   ```
   This will correctly read `SPI_CACHE_SCTRL_REG(0)` bit 2 (`SPI_CACHE_SRAM_USR_RCMD`), evaluate `ext_sram_mapped = true`, register the 4 MB PSRAM pool with `esp_alloc`, and allow `psram_avail_bytes >= 1_048_576` to instantiate `ActiveDecoder::Flac`.
2. **Flash Protocol Adherence**:
   Per safety invariants, the 1-flash limit was strictly honored. Staging and flashing the register fix requires a new authorized work order.
